# moziame2

# Voice Word Rain (Web Porting Ver.)

大学の制作・展示にてUnityで制作・発表したインスタレーション作品を、ブラウザだけでいつでも手軽に体験できるようJavaScriptで自主移植したデジタルアート作品です。

## デプロイURL (Google Chrome専用)
* **リアルタイム文字表示版:** https://taisyouzidai-sketch.github.io/moziame2/

## 使用技術・Web API
* **Frontend:** HTML5, CSS3, JavaScript (Vanilla JS)
* **Web Speech API (`SpeechRecognition`):** ユーザーの音声入力・リアルタイムテキスト化
* **Web Audio API (`AudioContext` / `BiquadFilterNode`):** 完全にコード上で生成する環境雨音のシンセサイズ、および音声連動によるダイナミックなフィルター・音量制御

##  技術的な工夫とブラウザ仕様（バグ）との戦い

### 1. ブラウザ独自の音声認識仕様と環境の制限（Chrome専用への割り切り）
MacやiOSのSafari（WebKit環境）においては、Web Speech APIの連続認識の制限や、Web Audio API（自作の雨音システム）との内部的なオーディオセッションの競合・衝突バグにより、マイクが強制遮断される現象が発生しました。
演出のクオリティや、声と雨音がシームレスに調和する世界観を妥協なく100%発揮させるため、本作品は音声認識エンジンが最も強力かつ安定している「Google Chrome専用」として設計・最適化するという現実的かつ最適な判断を行いました。

### 2. モバイル環境における物量（密度）の自動最適化
PCの大画面を想定した背景の文字（雨）の降下確率をそのままスマートフォン（狭い画面幅）に適用すると、文字同士が激しく重なり合い、画面が文字で埋め尽くされて真っ白に潰れてしまう視覚的な問題が発生しました。
これに対し、JavaScript（gameLoop関数）側で動的に画面横幅（window.innerWidth）を検知するロジックを実装。スマホ環境の時だけ自動的に「背景文字の生成確率を間引くフィルター（三項演算子による確率制御）」を通すように設計しました。
これにより、文字サイズ自体のダイナミックなランダム感や演出の心地よさは原作（Unity版）のまま一切損なうことなく、スマホの細い画面幅にも美しくおさまる上品な雨の密度を保つ操作性を実現しました。

### 3. モバイルブラウザ特有のUI回避
スマートフォンのブラウザ（特にモバイル版Chrome/Safari）で発生する、下部ツールバー（戻る・進むボタン等の操作バー）による画面の見切れ問題を回避するため、CSSの最新単位である `100dvh`（Dynamic Viewport Height）を導入。操作バーの出現に合わせてステージの床が自動で追従し、文字がボタンの裏に隠れることなく綺麗に足元に積もるように設計しました。
